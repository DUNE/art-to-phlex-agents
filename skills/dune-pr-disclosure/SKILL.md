# AI disclosure on DUNE commits and pull requests

## Pull request

End the pull request description with one line:

- `🤖 Generated By: <tool> (<model>)` when the model wrote the change and the person reviewed
  it. A phase-1 art-to-Phlex pass made by the extractor agent is this case.
- `🤖 Assisted By: <tool> (<model>)` when the person wrote or substantially reworked the
  change with AI help.

Example: `🤖 Generated By: Claude Code (Opus 5.5)`.

Check the tool and model against the session information. If you do not know the model
version, ask; do not guess. If several models did the work, name the one that wrote the
change.

Ordinary editor completion needs no footer.

## Commits

Add a git trailer to every commit that AI wrote or helped with, on the last line of the
message after a blank line. Use the same choice as the pull request footer:

```text
Fix CMake test registration

Generated-by: Claude Code (Opus 5.5)
```

or `Assisted-by: <tool> (<model>)`. Use exactly these keys so that `git log
--grep='^Generated-by:'` and `git interpret-trailers` find them. No emoji in trailers.

Do not use `Co-Authored-By` for an AI tool; the tool is not an author. If the tool adds that
trailer automatically, turn it off (in Claude Code, set `attribution.commit` to `""`, as the
kit's `.claude/settings.json` does) and add the trailer above instead.

With squash merging, keep the trailer in the squashed commit message.

*Follows the draft DUNE AI usage policy (DUNE collaboration meeting, Campinas, September
2026). Not yet adopted.*
